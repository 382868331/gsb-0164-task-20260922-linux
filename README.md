# 闪存页映射的断电搬迁与磨损管理（合成 FTL）

一个**离线、零第三方依赖**的合成闪存转换层（Flash Translation Layer）可复用库：
16 块 × 每块 8 页 × 每页 32 字节；整块擦除、页只能从空白态写一次；
逻辑页覆盖写通过“新数据页 + 带 CRC32 的映射提交记录”实现，**提交记录完整
落盘后映射才可见**；支持在每次页写 / 块擦除之后注入掉电，并在重新挂载时
扫描序列号恢复最后一个完整映射；垃圾整理先搬迁仍有效的页（以及仍生效的
映射记录）再擦除受害块；坏块永不参与分配；每块擦除次数受调用方给定上限
约束。

仅使用 Python 3.14 标准库（`zlib` 提供 CRC32），不调用任何第三方 FTL/存储
实现，也不访问网络、数据库、硬件或云服务。示例数据全部由仓库内确定性代码
生成。

## Python 版本与依赖

- Python **3.14.7**（标准库；任何 3.10+ 也能运行，但以 3.14.7 验收）。
- **无额外依赖**：`requirements.txt` 仅为占位说明，`pip install` 任何东西都
  不需要。Linux 原生运行。

### 几何与常量

| 名称 | 值 | 含义 |
|---|---|---|
| `BLOCKS` | 16 | 块数 |
| `PAGES_PER_BLOCK` | 8 | 每块页数 |
| `PAGE_SIZE` | 32 | 每页字节数 |
| `MAX_LOGICAL_PAGES` | 128 | 合法逻辑页号 0..127 |
| `MAX_PAYLOAD` | 26 | 单次逻辑写最大载荷字节 |

每页一帧 32 字节：`tag(1) | CRC32(4, 大端, zlib.crc32) | body(27)`。

- 数据帧 `tag='D'(0x44)`：`body = 长度(1) + 载荷(≤26)`。
- 提交帧 `tag='C'(0x43)`：`body = 序列号(3 字节大端) + 最多 4 个映射项`，
  每项 6 字节 = 逻辑页号 3 字节 + 物理页号 3 字节；未用槽位为全 `0xFF`。
  因此 `write_pages` 一次最多原子提交 **4** 个逻辑页。
- 序列号为 24 位（0..16_777_215）；写满后抛 `SequenceExhaustedError`，
  不做静默回绕。

### `RawFlash`（原始介质）

```python
RawFlash(blocks=16, pages_per_block=8, page_size=32,
         bad_blocks=frozenset(), bad_pages=frozenset(),
         program_faults={}, erase_faults={})
```

- `program(ppn, data32)`：只能写空白页；对非空白页或坏页抛
  `PhysicalMediaError`，且**不改变**介质（拒绝，而非半写）。
- `erase(block)`：整块复位为空白并自增该块擦除计数；坏块抛 `BadBlockError`。
- `bad_blocks`：出厂坏块，擦除永远失败；`bad_pages`：声明的坏页，FTL 以块
  为替换粒度，在挂载时把含坏页的整块隔离。**坏块永不再被分配或擦除。**
- `program_faults` / `erase_faults`：`{动作序号: "lose_after"}`。语义为该
  序号的页写 / 块擦除**本身已完成并持久化，但在动作成功返回的瞬间掉电**，
  随即抛 `PowerLossError`。序号按该类动作从 0 计数。
- 属性：`action_log`（`RawAction` 的权威物理动作时序日志）、`erase_counts`、
  `quarantined_blocks`、`read_raw`、`is_blank`、`snapshot/restore`（仅供
  测试 / 演示建模，不是闪存原语）。

### `FTL`（映射层）

```python
ftl = FTL(raw_flash, max_erases_per_block=1000)
ftl.write(lpn, data)                 # 提交 1 个逻辑页（data 0..26 字节）
ftl.write_pages({lpn: data, ...})    # 1..4 个逻辑页在同一提交下原子可见
ftl.read(lpn)                        # 读取该逻辑页最后已提交载荷 -> bytes
ftl.force_gc()                       # 立即整理一个受害块，返回块号
ftl.mapping                          # dict[lpn -> ppn] 的防御性副本
ftl.physical_events                  # 物理动作日志（program/erase 时序）
ftl.logical_events                   # 逻辑读写事件日志
ftl.capacity()                       # 剩余容量与磨损账目（见下）
ftl.block_view()                     # 每块逐页分类：空白/有效/陈旧/提交/撕裂
ftl.next_sequence                    # 下一个提交序列号
```

`max_erases_per_block`（必填，非负 31 位整数）是每块擦除次数的硬上限：
达到上限的块仍可写完其剩余空白页，但**不会再被选为 GC 受害块**。

`capacity()` 字段：

- `free_physical_pages`：非坏块上当前可写的空白页（**含**保留的 1 个 GC
  工作块，共 8 页）。
- `free_without_reserve`：在始终保留 1 个全空搬迁工作块前提下，普通写可
  立即使用的页数。
- `gc_reserve_pages`：工作块保留量（0 或 8）。
- `live_data_pages`：当前映射指向的有效数据页数。
- `garbage_pages`：健康、未到磨损上限块上的非有效占用页（陈旧数据 / 提交
  记录 / 撕裂帧）。这是**占用量**，不保证都能“盈利”回收。
- `profitable_gc_available`：当前是否至少存在一个净增空白页严格为正、且有
  单块搬迁空间的受害块。
- `stranded_pages`：GC 永远拿不回的页（坏块整页 + 磨损封顶块上的占用页）。
- `erase_counts` / `wear_headroom` / `bad_blocks` / `mapped_logical_pages`。

## 错误语义

| 错误 | 触发与保证 |
|---|---|
| `FTLValidationError` | 非法入参。数值拒绝 `NaN`/`±Infinity`；整数参数拒绝 `bool`（`True/False`）与浮点（含 `1.0`）；越界、类型不符、载荷 >26 字节、批大小不在 1..4、批内重复逻辑页等。**校验先于任何状态变更，被拒绝的调用不产生任何物理动作、不做静默纠正。** |
| `FormatMismatchError` | 挂载的 `RawFlash` 几何不是 16×8×32。 |
| `UnmappedLogicalPageError` | 读取从未成功提交的逻辑页（同时是 `KeyError`）。 |
| `PhysicalMediaError` / `BadBlockError` | 违反 NAND 访问契约（重复写非空白页）/ 擦除坏块（`OSError` 子类）。 |
| `StorageFullError` | **证明当前无解**：无健康、未到磨损上限、净收益为正且有单块搬迁空间的受害块。穷尽搜索全部 16 块后给出，不是“搜索预算耗尽”。 |
| `WearLimitError` | 存在可回收块，但**所有**候选都已达到 `max_erases_per_block`。与真正写满分开报告。 |
| `SequenceExhaustedError` | 24 位提交序列号用尽。 |
| `PowerLossError` | 掉电注入：物理动作已成功后掉电。当前 FTL 实例立即失效；对同一 `RawFlash` 重新 `FTL(...)` 即完成“重启恢复”。 |
| `FTLInternalError` | 核心自身不变量被破坏（库的 bug，而非坏入参）。 |

“搜索预算耗尽 vs 证明无解”的区分：受害块选择对至多 16 块做**穷举**判定，
要么选出一个可行受害块，要么证明不存在并抛 `StorageFullError` /
`WearLimitError`；不存在超时式的预算截断。

## 设计取舍（关键）

1. **提交原子性**：先写数据页（此时为不可达孤儿），最后写带 CRC32 的提交
   帧；内存映射只在提交帧落盘后更新。掉在提交前 => 重启扫描忽略孤儿数据；
   掉在提交后 => 映射可见。恢复时按 `(序列号, 物理位置)` 升序折叠提交帧，
   且仅当提交帧 CRC 正确、它引用的每个数据页都可读时才接受，故“最后一个
   **完整**映射”决定可见逻辑映像。撕裂 / CRC 坏帧一律忽略。

2. **搬迁必须保住两类“活信息”**：擦一个块会同时毁掉其中的有效**数据帧**和
   仍在生效的**提交记录**（一条提交记录可能映射着数据已在别的块上的逻辑
   页）。GC 计划同时计算 `copy_items`（数据要搬走）和 `assert_lpns`（数据
   已在别处、只需在新提交帧里重新断言映射项）。只有在全部搬迁提交持久化
   之后，才允许擦除受害块。

3. **单块搬迁目标 + 空闲块保留**：只要健康块 ≥2，就**无条件**保留 1 个全
   空块作为搬迁工作区，普通写不消耗它；一次 GC 的所有新帧写入同一个目标
   块（净收益 >0 保证 ≤7 页，单个 8 页块放得下）。受害块擦除后成为新的
   全空工作块。这样杜绝“吃掉最后空白块后无第一步合法搬迁”的死锁。

4. **搬迁掉电幂等**：搬迁中途掉电后，已落盘但尚未提交的数据副本仍是孤儿；
   重启时 GC 前滚，**按内容匹配复用**这些孤儿副本（载荷一致、块健康、未被
   任何映射指向），再补齐提交与擦除。任意页写 / 块擦除之后掉电，恢复后
   “已提交映射”与“可读介质”始终一致：未提交副本是孤儿，已提交副本使旧页
   自然成为陈旧垃圾。

5. **磨损策略**：工作块选取磨损**最高**的全空块，普通写先消耗磨损较低的块，
   低磨损块随后被擦除以追赶，贪心把各块擦除次数差控制在约 ≤1。受害块在
   资格满足时按“搬迁项更少、擦除次数更少、块号更小”选取。

6. **坏块**：出厂坏块（`bad_blocks`）与含声明坏页的块（`bad_pages`）在挂载
   时整体隔离；隔离块的页永不分配，块永不擦除。

## 测试与独立参考

`python -m unittest discover -s tests -v` 覆盖：

- 短写轨迹在**每个页写断电点**的恢复，逐点与 `tests/reference.py` 独立推导
  的“已提交前缀映像”比较（参考模型**不导入** `ftl_core`，期望值来自契约
  算术；往返一致仅作补充）。
- GC 场景下**每个块擦除断电点**、密集页写断电点、写/擦双故障注入下的恢复
  与续跑完成；恢复后映射自洽（每个映射指向不同且可读的数据帧）。
- 多页批原子可见性、孤儿数据回收、重启后序列号单调不复用。
- GC“先搬迁后擦”不变量（擦块瞬间不允许映射指向该块）、坏块不分配、坏页整
  块隔离、多坏块导致干净的空间不足。
- 磨损上限：无块超限；磨损在块间均匀分布；`WearLimitError` 与
  `StorageFullError` 分别触发。
- 帧编码往返、用独立位级 CRC32 实现交叉校验、坏 CRC / 未知 tag 被拒。
- 输入校验（NaN/Infinity/bool/float/越界/类型/长度）且拒绝不留物理动作。

## 输入上限（接口边界）

- 固定几何：16 块、每块 8 页、每页 32 字节，逻辑页号 0..127。
- 单逻辑页载荷 0..26 字节；`write_pages` 每批 1..4 页；更大载荷不自动分片。
- `max_erases_per_block`：0..2^31−1 的整数。
- 序列号 24 位（0..16_777_215）。
- 故障注入字典的键为非负整数动作序号，值仅接受 `"lose_after"`。

## 数值 / 误差口径

本库的所有输出（容量、擦除计数、序列号、物理 / 逻辑日志）都是**整数或字节
串，精确无浮点**，因此**不存在浮点误差或容差**；也不用宽容差掩盖边界判定。
输入侧的数值一律按“有限实数 / 严格整数”校验，`NaN` 与 `±Infinity` 直接拒绝。

## 已知限制（按本题契约的有限子集）

- 不宣称兼容任何行业标准 FTL / ONFI / UBI 等；这是题面契约下的教学级合成层。
- 不做跨页 / 跨提交的载荷分片：单逻辑页最大 26 字节，超出即拒绝。
- 介质为进程内字节数组；“持久化”语义由 `RawFlash` 的严格写/擦模型与故障
  注入表达，不接真实 NAND、文件落盘或块设备（`snapshot/restore` 只是测试
  辅助）。
- CRC32 检测帧位损坏，但不做 ECC 纠错；声明坏块 / 坏页是确定性输入，不
  模拟读写随机位翻转率。
- GC 为单线程、确定性贪心策略；不实现动态超额配置调节、热冷分离或压缩去重。
